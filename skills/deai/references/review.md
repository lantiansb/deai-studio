# 验收：检查产物，而不是给“AI含量”打分

## 先检查可核对的事项

| 类别 | 检查内容 | 失败时怎么做 |
| --- | --- | --- |
| 内容取舍 | 所有可见句子、标签、图中道具和重复小字是否服务读者此刻的任务或明确表达；有无制作上下文泄漏；减法是否误删必要信息 | 按 [内容取舍](content-selection.md) 删除、转译或移位；反查条件与用户保留项，不以“真但无关”为保留理由，也不按禁词表误删 |
| 事实与范围 | 数字、单位、对象、时间、条件、否定、承诺和不确定性是否保持；新增信息是否有依据 | 修正或删除无依据内容，必要推断明确标出 |
| 用户保留项 | 品牌、批准过的版本、角色设定、文档条款、格式、编辑范围 | 恢复保留项，避免用插件偏好覆盖用户指令 |
| 行为 | 主要操作是否实际完成；提交失败、键盘、焦点、窄屏是否可用 | 修复行为再评价视觉；模拟功能清楚标明 |
| 文件 | 真实格式、可打开、内容完整、可编辑性符合要求 | 用相应工具修正，不能把 Markdown 改后缀当 Office 文件 |
| 可见结果 | 图片结构，页面布局，PPT/文档渲染后的遮挡、裁切、缺字与阅读顺序 | 查看实际输出后修正；不能只凭源码宣称视觉通过 |

## 再做具体的审美判断

检查焦点是否清晰；形式是否说明内容关系；装饰和动效是否挤占信息；表达是否有依据；媒介和风格是否自洽。指出位置及影响，例如“第二页三项证据权重不同，等宽卡片让读者误以为同样重要”。不要只写“还很AI”“更高级了”。

改动应与问题对应。文字自然且准确就保留；有设计依据的高密度画面不必强制简化；同类数据对比不为了版式丰富而破坏一致比例。

## 不同产物的最小验证

- 文字：逐项核对事实；朗读或通读，检查对象、主语、重复和衔接。短改稿无需建立测试工程。
- 图片：查看全图与重要局部，检查识别性、结构、焦点、媒介和无意增加的纹理。没有参考图时不得宣称身份或产品外观精准一致。
- 前端：打开实际页面；完成主操作；检查至少一个窄屏、键盘焦点和 reduced-motion。静态展示可按实际复杂度缩减。
- PPT：确认页数与顺序、源数据、文本及图表可编辑性；渲染全部页面检查溢出与对齐。
- 文档/PDF：检查内容与条款；渲染全部页面；核对标题层级、表头、页码、断页及所需导航。表格还要检查公式、单位和可复算结果。

没有相应渲染器或宿主功能时继续完成可做检查，并把缺口写为“未验证”。不要把生成成功当成渲染通过，也不要声称未做过的读屏或跨平台测试。

## 比较实验与偏好

比较技能使用前后时保留同一原始请求、输入资料、模型条件及完整结果。记录是否新会话、工具差异、选择过的候选数；不能故意把基线写差。少量试用只说明这些样例的现象，不能给出成功率或保证一稿满意。

让用户按用途和喜好判断，不把自身点评伪装为用户盲评。用户指出问题后，保存其认可的版本，并记录“什么保留、什么减少、什么改变”。没有新反馈就不反复重抽直到自称通过。

复杂产物可请求独立复审，复审者应看到原始需求和真实产物。最终说明仅报告重要结果、做过的检查和仍存在的限制；无需为每个小任务附大段内部流程。
