# 交互选型：先确定行为，再选择实现

## 一次只解决一个实际关系

先写清触发动作、状态变化、反馈、撤销或退出方式。只为了让静态页面显得活跃的动画通常可删；品牌发布、游戏或作品集可以把运动作为主要表达，但仍需可读、可操作。

| 场景 | 适合的模式 | 必须保留的行为 |
| --- | --- | --- |
| 项目目录、作品索引 | 行与预览对应，焦点或指针切换 | 键盘也能查看，触屏点击可达，不依赖 hover 才出现必要信息 |
| 同一对象的少量视图 | 分段标签与连续指示器 | 方向键、选中状态、面板关联；不把页面导航误写成 tabs |
| 次要说明 | 行内展开 | 语义化 details/summary；关键信息不默认隐藏 |
| 提交、保存 | 实际请求的等待、成功、失败状态 | 防止重复提交、保留输入、失败重试；不能用计时器冒充真实进度 |
| 隐藏或移除条目 | 明确结果及撤销 | 焦点去向可预测；有合理恢复方式，必要内容不只靠转瞬即逝的 toast |
| 长篇阅读 | 章节锚点与局部阅读进度 | 原生链接仍可用；进度属于当前阅读区域，不是凭空的完成度 |
| 表单和复杂应用 | 稳定的焦点、菜单、弹层及错误反馈 | 优先成熟无障碍原语，装饰动画不能破坏原语语义 |

以上六种基础模式的原创代码在 [离线实验](../assets/interaction-lab/index.html)。先阅读其 [说明](../assets/interaction-lab/README.md)，挑选所需模式，不默认复制整页样式。它们是轻量教学实现，复杂菜单、弹窗、虚拟列表使用成熟组件。

## 按现有技术栈选择

默认先用 HTML、CSS 与浏览器原生 API。已有依赖能满足需求就复用，不为了去AI味引入第二套动画引擎。外部包只有在实际项目允许安装、许可与版本已检查时才引入；本插件不自动下载。

| 需要 | 候选 | 本插件处理方式 |
| --- | --- | --- |
| React 状态过渡、布局关联 | Motion 核心；已有 react-spring 项目继续使用 | 索引官方文档，核心包 MIT；增值内容另行核实 |
| 精细时间线、多元素编排 | Anime.js；已有 GSAP 项目评估 GSAP | Anime.js MIT；GSAP 是自定义许可，不称为 MIT，也不随插件打包 |
| 焦点、选择、菜单与覆盖层 | Radix、React Aria | 根据框架及现有组件体系二选一，保留语义和键盘行为 |
| 浮层定位 | Floating UI | 它负责定位，不能据此宣称整个组件已完成无障碍 |
| 高表现力视觉案例 | Codrops、React Bits | 只用作参考；单独检查代码、素材和依赖许可。React Bits 有组件再分发限制，不收录其源码 |
| 抽屉手势研究 | Emil Kowalski 的抽屉文章、Vaul | 文章用于理解滚动和拖拽冲突；Vaul 当前不维护，不作为新项目默认依赖 |

完整链接与核验记录见 [UI 与动效研究](../../../docs/research/ui-motion.md)。不要把库名写成审美保证。

## 参考真人署名作品的方法

从案例提取一条可解释的原则，例如“切换时用位置连续性说明仍是同一组内容”，然后围绕当前业务独立实现。不要复制品牌、文案、素材或整段未授权代码；署名案例也不构成作者从未使用 AI 的证明。

- [Rauno 的交互作品](https://rauno.me/craft)：观察小控件、输入、预览和选中状态之间的连续关系。先选一个相关案例，不把所有效果叠加。
- [Emil 的抽屉复盘](https://emilkowal.ski/ui/building-a-drawer-component)：检查滚动与拖动的竞争、手势打断、软键盘和真实设备条件。
- [Linear 的界面改版复盘](https://linear.app/now/how-we-redesigned-the-linear-ui)：减少视觉噪声，同时让层级和导航密度服务使用者；不要只提取深色背景。

## 实现与验收

运动幅度和时长取决于距离、任务与反馈。微小状态变化应迅速，较长空间变化应可跟踪；不要对所有组件机械指定同一弹簧。优先 transform/opacity，但仍实测布局、焦点与可访问名称。

至少检查鼠标、键盘、触屏窄屏、reduced-motion，以及请求失败/重复点击/中断。JS 不可用时保留适用的基础内容；确需脚本的控件不要呈现为可用却没有反馈。不要抢占系统光标、强制平滑滚动或阻塞正常导航。
