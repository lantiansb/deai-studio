# 文档编辑：结构、格式与阅读效果

本参考处理文档体裁及文件质量；主入口已负责任务识别、材料读取、媒体路由和交付。
方法出处与许可说明见[文字与文档研究](../../../docs/research/writing-documents.md)。以下为原创整合，不转载上游指南。

## 按读者用途选择结构

| 文档 | 组织重点 | 必须保留的边界 |
| --- | --- | --- |
| 报告、复盘 | 结论与范围、证据、解释、风险、待决事项 | 数据来源、口径、期间；观察与归因分开，未测量的效果不写成成果。 |
| 方案、提案 | 问题、建议范围、交付物、资源、依赖、里程碑、验收 | 已有预算、责任与承诺不能漂移；缺项标明待确认，不编造 ROI 或案例。 |
| 技术教程 | 前提、可完成的学习任务、步骤、可观察结果 | 环境与版本、关键步骤、失败处理不能为简洁而省掉。 |
| 操作指南、参考、解释 | 分别服务于完成任务、查准信息、理解原因 | 不把背景论述塞进紧急操作步骤；接口、单位、错误码准确。 |
| 公开说明、FAQ | 适用人群、变化、时间、行动、限制、联系渠道 | 只写经确认的安排；必要时写明时区，不补无依据的安抚。 |
| 表格、清单 | 让平行信息可比较、可计算、可执行 | 表头、单位、来源、分类、空值含义和状态定义明确。 |

这些是判断问题，不是每份文档必须套用的章节。短通知无需执行摘要，小提案无需凑齐长报告目录。
用户只给短提示时，依据受众、用途和交付格式自行选择合理结构；只把确实缺失的事实列为未决项。
按 [内容取舍](content-selection.md) 检查每个背景段是否帮助读者完成当前任务。排版要求、生成过程和工具说明默认留在交付记录；不要因为材料提到过就添加到正文，也不把无关的缺失字段都列为待确认。必要条件、义务、引文和阅读所需结构仍应完整保留。
服务范围等正式短文件，将包含项、排除项、时限边界和待确认事项各集中说明一次。不要每个小节反复解释“本说明未约定”，也不要为显得谨慎增写用户没有提出的风险和防御性条款。
资料只支持半页正文时，通过清楚的标题和间距形成约一页文件，不靠同义重复、泛泛解释或新增义务填满页面。没有给出的报价和日期可以在文末一个待确认处处理，不能假定为已达成。
长报告的摘要应呈现结论及关键限制；提案的预期结果与报告的已验证结果分开表述。
装饰性大字、卡片或图标不能替代证据和正文；字号、行距、行长先服务于连续阅读。

## 编辑现有文件时保留的结构

- 保留语义标题及合理层级；视觉加粗、字号放大不能替代真实标题样式。
- 保留列表类型、编号连续性与引用关系；章节重排后同步核查文内编号和交叉引用。
- 保留脚注、尾注、书签、超链接、题注、目录字段、页码及必要修订记录；不要无意压平成普通文字。
- 保留表头、单位、注释、合并关系和来源；跨页表格注意重复表头和行被截断的问题。
- 图表、图片和正文互相核对；图注不能新增证据，替代文字说明实际内容，不能自动虚构图中信息。
- 内容润色不自动授权改版。已约定的品牌、模板和文档规范优先于通用审美偏好。

## Word / DOCX

- 用段落和字符样式管理正文、标题、引用、题注等角色；优先保持现有样式关系与自动功能。
- 采用真实段落、列表、表格和分页机制，不靠成串空格、空行或文本框拼出正文阅读流。
- 处理长文时核查标题是否与正文分离、表格是否溢出、页眉页脚是否遮挡内容、目录页码是否更新。
- 需要可编辑交付时保留正文和表格的可编辑性；整页截图放进 DOCX 不能代替可编辑文档。
- 若要求修订或保留批注，使用支持这些功能的工具；无法可靠保留时应明确限制，不能悄悄丢弃。

## PDF

- 有可编辑源文件时优先在源文件修改，再导出 PDF；不要把可编辑正文先截图再重新封装。
- PDF 是实际文件格式，不是文件扩展名。导出后核对文字、图表、分页与字体效果。
- 需要可搜索文本时检查文本提取；需要可访问性时另查标签、标题和阅读顺序，不能凭外观判断。
- 多栏、边注和复杂表格容易出现阅读顺序问题；按实际顺序检查，不仅看页面缩略图。
- PDF/A 的归档属性不等于可访问性；“能复制文字”也不代表标签和键盘导航正确。
- 只有 PDF 且编辑工具能力有限时，区分直接编辑与重新制作；说明可能影响的版式或结构，不假装无损。

## Markdown

- 使用语义标题、真实列表、引用、代码块和描述性链接；标题层级为阅读服务，不为凑结构。
- 代码围栏语言、缩进、列表起始编号和表格转义需要正确；不要把命令中的标点当普通文字润色。
- 保留链接目标和相对路径的语义；移动文件或重排标题后核对内部链接。
- 在目标渲染器中检查长表格、嵌套列表和代码块；纯文本语法正确不保证所有平台显示一致。
- Markdown 适合作为可编辑正文来源，但不能把它重命名成 `.docx`、`.pdf` 或 `.xlsx` 作为交付。

## 表格与电子表格

- 叙述型文档中的表格用于比较真实的平行信息；顺序步骤用列表，连续论证用段落。
- 保留工作表名称、单元格类型、公式、引用、筛选、验证规则和必要批注；不要把公式结果误写成永久值。
- 日期、百分比、币种和单位保持一致；空白、零、未知、不适用应有不同含义。
- 汇总说明必须与底层数据一致；不能为使结论更顺而修改数据、隐藏异常或省掉不利结果。
- XLSX、CSV、Markdown 表格能力不同；按要求交付真实格式，并明确不能保留的功能，例如 CSV 的多工作表和公式结构。

## 工具能力与检查

- 有对应文档、PDF、表格技能或工具时使用其实际能力；检查工具返回和文件内容，不凭名称推断成功。
- 有渲染器时查看生成页面；对较长文件先覆盖所有页面的版面，再细查复杂表格、图表和修改密集页。
- 有内容提取或结构检查能力时核对标题、编号、引用、文本和数据；渲染检查与内容检查不能互相替代。
- 没有渲染器时仍可检查已支持的内容与结构，但明确“未做渲染检查”；不能报告版式或可访问性已经通过。
- 指定格式无法生成时，交付当前可用的真实产物并说明缺口；不得伪造扩展名或声称已完成所需文件。
- 不因为缺一个工具而要求用户填写整套模板。继续完成独立可做的内容工作，只询问影响结果的关键缺失事实。
- 检查结论只描述本次实际做过的检查及其范围；“可打开”“渲染正常”“可编辑”“可访问”分别有不同证据要求。

最终文件中的结论、数字、来源、表格和正文应一致。源文件与导出件同时交付时，确认二者对应同一修订版本。
