# deai-studio：演示、信息设计与文档视觉调研

核查日期：2026-09-05。范围：官方方法介绍、项目文档及许可原文；未安装、下载或运行外部脚本。以下整合方案是本次调研的原创建议，不代表来源机构认可本插件，也不是“人类制作鉴定器”。

建议把“去 AI 模板感”落实为：让页面结构服务于内容关系，让视觉证据支持主张，让文字密度符合阅读场景。统一字体、网格和标注规则，但不统一成每页“大标题＋三卡片”。先区分现场演讲、独立阅读、教学操作、正式报告，再选择输出格式。

## 12 项来源与整合边界

### 1. Assertion–Evidence：从主张组织页面

- **官方来源：**[Assertion–Evidence Approach](https://www.assertion-evidence.com/)。用完整、简洁的消息组织技术演讲，并以图形证据支持消息。
- **许可／分发：**所查页面未声明适用于整个网站及模板的开放分发许可，列为**只参考**。插件自行编写规则、示例与版式；不打包站内课件、照片、视频或书籍图版。
- **是否 Codex 专用：**否；这是演示方法，与生成器无关。
- **具体整合：**每页保存 `claim`、`evidence`、`source`、`qualification`。先判断有什么可支持的结论，再选图表、标注图或关系图。没有证据时允许写研究问题、假设或待验证事项，不为凑“结论标题”把猜测改成事实。
- **适用体裁：**科研答辩、技术评审、实验结果、工程说明。议程、目录、练习题等功能页不必强制变成断言句。

### 2. Penn State Scientific Presentations：讲者、备注与教学复审

- **官方来源：**[Teaching Scientific Presentations](https://www.writing.engr.psu.edu/teaching_presentations.html)、[Engineering Ambassadors 指南](https://writing.engr.psu.edu/assertion_evidence_EA.html)。后者建议先写消息，再制作页面，将次要细节和讲述内容放入备注并练习讲解。
- **许可／分发：**教学页明确允许教师在教学中使用资源，但须署名网站及相应原作者。这是有语境的教学使用说明，**不据此推导插件可商业再分发课件**；本插件仍列为只参考。旧教学页直接访问不稳定，本轮通过官方域名的搜索索引核对了上述声明。
- **是否 Codex 专用：**否。
- **具体整合：**给现场讲解稿生成独立备注、术语解释和过渡句；检查只读标题是否能理解论证顺序。建立原创复审问题，而不复制其评价表。旧清单的字体大小、字数及行数适用于其演示场景，不设成所有中文页面的硬门槛。
- **适用体裁：**课程、学术演讲、团队技术报告；阅读型材料需把必要信息留在正文，不能全部藏进备注。

### 3. Duarte：受众与视觉焦点

- **官方来源：**[4 tips and 1 tool that will help you perfect your slide design](https://www.duarte.com/blog/perfect-your-slide-design/)。文章展示如何按受众筛选信息，以对比和留白建立焦点，并保持图像语言一致。
- **许可／分发：****只参考、不搬运**。本轮未见文章开放许可；不复制示范页、插图、测评工具、课程内容及品牌标识。
- **是否 Codex 专用：**否。
- **具体整合：**原创审查项询问“第一眼先看哪里”“这张图是否帮助理解”“哪些细节属于讲述”。其 Glance Test 是面向演讲的经验方法，不把“三秒理解”包装成科学证明或长文档的普适合格线。
- **适用体裁：**现场提案、产品介绍、公众沟通；会前阅读文件需另外设计阅读层级。

### 4. PptxGenJS：可编辑 PPT 的主要候选

- **官方来源：**[功能与对象模型](https://gitbrent.github.io/PptxGenJS/docs/introduction/)、[MIT 许可原文](https://github.com/gitbrent/PptxGenJS/blob/master/LICENSE)。支持文字、形状、表格、图表、图片及母版，输出 OOXML。
- **许可／分发：****MIT**；分发代码或实质性副本须保留版权和许可声明。输入素材、字体及其他依赖单独核查。
- **是否 Codex 专用：**否；通用 JavaScript 库。
- **具体整合：**作为 `editable-pptx` 默认适配器，把内容模型映射到原生文字、形状、表格和可支持的原生图表。共用排版令牌与坐标记录，生成后检查 OOXML 并实际渲染。图片仍然是图片；库能写文件不等于自动解决排版或 Office 兼容性。
- **适用体裁：**需用户改字、改数字、调整图表的商业汇报、科研评审、教学课件。

### 5. Marp：轻量 Markdown，明确两种 PPTX 路径

- **官方来源：**[Marp CLI README：导出说明](https://github.com/marp-team/marp-cli#convert-to-powerpoint-document---pptx-)、[MIT 许可原文](https://github.com/marp-team/marp-cli/blob/main/LICENSE)。
- **许可／分发：**所查 Marp CLI 为 **MIT**，保留声明；额外主题、字体、浏览器及转换依赖各自核查。
- **是否 Codex 专用：**否；通用 Markdown 转换工具。
- **具体整合：**适合快速编写技术讲义、版本可追踪的简报。默认 PPTX 是预渲染背景图片，不能按原生文本编辑。当前提供实验性 `--pptx --pptx-editable`，需浏览器和 LibreOffice Impress；官方提示复杂样式可能不完整、还原度较低且不支持演讲备注。故可编辑模式只作明确标注的实验选项，并经逐页验证。
- **适用体裁：**内部分享、培训、简洁讲义、HTML/PDF 交付；严格要求可编辑及还原度的客户 PPT 优先用原生对象生成器。

### 6. reveal.js：内容需要交互时使用

- **官方来源：**[reveal.js 文档](https://revealjs.com/)、[许可原文](https://github.com/hakimel/reveal.js/blob/master/LICENSE)。HTML 演示框架，支持代码、公式、备注及 PDF 导出等。
- **许可／分发：****MIT**，保留声明；插件和媒体资源另审。
- **是否 Codex 专用：**否。
- **具体整合：**提供可选 `html` 适配器，供代码高亮、逐步推导、嵌入式演示使用。交互只用于解释变化或操作，默认减少过渡效果；同时生成可独立理解的静态版本。不能把 HTML/PDF 支持说成原生可编辑 PPT 支持。
- **适用体裁：**开发者演讲、交互课程、产品原型演示；需要离线分享时检查资源是否完整。

### 7. Quarto：同一内容来源连接幻灯片与正式报告

- **官方来源：**[PowerPoint 文档](https://quarto.org/docs/presentations/powerpoint.html)、[quarto-cli COPYING.md](https://github.com/quarto-dev/quarto-cli/blob/main/COPYING.md)。支持通过 Pandoc 输出 PPTX，使用 `reference-doc` 定义母版，并支持多栏及演讲备注。
- **许可／分发：**本次核查的 **quarto-cli 主仓库 main 为 MIT**。这不代表其安装包、Pandoc、渲染器、扩展、字体全部是 MIT；若打包完整运行时必须逐项核查，不能沿用对旧版本的印象。
- **是否 Codex 专用：**否。
- **具体整合：**提供可选的研究／报告适配器，保留 `.qmd`、数据及引用来源，使用原创参考母版。文字和表格可走 PPT 原生结构；计算生成的图形不应默认承诺为可编辑 Excel 图表。PPT 与报告共用事实来源，但分别组织密度与叙事。
- **适用体裁：**研究报告、定期数据汇报、方法说明、需要配套长文的学术材料。

### 8. Slidev：技术讲解丰富，PPTX 为图片

- **官方来源：**[Slidev 导出指南](https://sli.dev/guide/exporting.html)、[MIT 许可原文](https://github.com/slidevjs/slidev/blob/main/LICENSE)。
- **许可／分发：****MIT**，保留声明；社区主题、插件和资源另审。
- **是否 Codex 专用：**否；通用 Markdown／Vue 演示工具。
- **具体整合：**作为技术课程的可选 HTML 适配器，保留 Markdown/Vue 源文件。官方明确 PPTX 每页导出为图片、文字不可选中，备注可随页保存；因此该导出归为 `raster-pptx`。逐步出现的内容会影响导出页数，须检查最终展开状态及页数。
- **适用体裁：**代码示例、技术教学、交互说明；适合浏览器呈现，不能凭 `.pptx` 扩展名承诺对象可编辑。

### 9. baoyu-slide-deck：可借鉴可追溯的图片工作流

- **官方来源：**[JimLiu/baoyu-skills 中的 SKILL.md](https://github.com/JimLiu/baoyu-skills/blob/main/skills/baoyu-slide-deck/SKILL.md)、[合并脚本](https://github.com/JimLiu/baoyu-skills/blob/main/skills/baoyu-slide-deck/scripts/merge-to-pptx.ts)、[MIT 许可原文](https://github.com/JimLiu/baoyu-skills/blob/main/LICENSE)。本轮所见技能版本为 1.117.4。
- **许可／分发：**仓库 **MIT**，改编需保留声明；模型服务、生成结果使用条件及输入素材权利不由此许可自动覆盖。
- **是否 Codex 专用：**否；当前技能含 Codex、Cursor 等运行时分支。
- **具体整合：**借鉴“来源→大纲→逐页完整提示词→生成图→合并”的留档与单页重做。它明确面向阅读分享，以整页图像组成 PPT；不能作为可编辑 PPT 默认路线。插件应重写能力适配层，按当前工具文档调用，不照搬工具名、耗时承诺及关键词自动选风格规则。
- **适用体裁：**视觉故事、分享型图文、艺术方向样稿。正式数据、引文和密集文字优先用原生排版；没有实证素材时，生成图须标为示意，不能冒充研究或顾客证据。

### 10. Financial Times Visual Vocabulary：新闻编辑按数据关系选图

- **官方来源：**[FT Visual Vocabulary](https://github.com/Financial-Times/chart-doctor/blob/main/visual-vocabulary/README.md)、[官方模板仓库及 Licence 段落](https://github.com/ft-interactive/visual-vocabulary-templates#licence)。这是新闻编辑训练资源，将图形选择联系到偏差、相关、排名、分布、时间变化等关系。
- **许可／分发：**模板仓库明确软件为 **MIT**，同时明确 **FT 内容及品牌不在 MIT 范围内**。本方案对海报和编辑示例只参考；若复用软件须去除受限内容并保留许可，不能把整个 FT 图表视觉包直接分发。
- **是否 Codex 专用：**否。
- **具体整合：**让 `data_relation` 与数据形态驱动图种候选，再检查轴、分母、时间窗及不确定性；使用原创样式和用户数据。用真实分布或同尺度小多图替代没有比较依据的 KPI 卡片。
- **适用体裁：**新闻解释、经营分析、政策报告、数据密集的阅读材料。

- **是否 Codex 专用：**否。
- **具体整合：**文档导出使用真实标题层级、表头和阅读顺序；表格用于数据，正文不烘焙进图片。保留可访问的源文档／HTML 版本。采用其可读性原则，不把特定政府发布政策误写为所有用户的法律义务。
- **适用体裁：**白皮书、指南、政策说明、面向公众的报告；有助于修正“看起来像杂志却无法检索、读屏或维护”的问题。

- **适用体裁：**长文档、编辑式阅读页、双语材料及跨导出引擎的统一排版。

## 六种内容驱动的页面结构

以下为原创结构建议。选择依据是“这一页的内容关系”，不是按页码轮换六种皮肤；对象数量由材料决定。一个文件可以混用，但延续相同文字层级、标注规范和数据口径。

| 结构 | 内容触发与页面组织 | 可编辑 PPT 做法 | 整页栅格的边界 |
| --- | --- | --- | --- |
| **结论＋证据** | 已有可支持的发现：句子标题、占主要面积的图表／证据图、直接标注、条件与出处 | 原生图表、可编辑标题和标注；证据照片原样嵌入 | 可用于视觉样稿；禁止生成不存在的实验证据，文字与数据另有可核对来源 |
| **机制／系统关系** | 要解释组成、因果或工作方式：系统图、局部放大、箭头语义、边界条件 | 原生节点、连接线与标签；复杂科学图可嵌矢量图并保留源文件 | 适合艺术化概念说明；真实结构、连接关系和图中文字须复核 |
| **选择／权衡** | 需要做决定：按实际候选数设计标准矩阵、权衡坐标或成本构成，说明推荐与假设 | 原生表格／图表，权重与来源保留在数据文件或备注 | 不适合需经常改分数、价格和权重的正式决策材料 |
| **变化／时间** | 要看趋势或干预前后：共用尺度的时间轴、小多图或前后对照，标事件及差异 | 原生折线、时间标签和事件注释；照片前后对照保持可比范围 | 仅当照片／图像是核心材料时考虑；不能为视觉戏剧性改变尺度或凭空补数据 |
| **编辑式证据页** | 独立阅读需要上下文：摘要、主文、证据图／表、图注、方法或来源侧栏 | 可编辑正文与图表，明确阅读顺序；过密时拆成两页或改成长文 | 适合分享预览；正式报告应另交可检索、可访问的文本版本 |
| **标注实例／教学推导** | 通过具体对象学习：原始样本、关键局部、逐步推导或操作反馈；页尾给检验任务 | 原生代码／公式／说明文字与编号，样本图保持真实；必要时分步或分页 | 可做插画教学，但精确代码、公式、操作界面及答案不要依赖生成文字 |

减少模板感时应保留有意义的重复：一组可比实验用相同版式反而更易读。卡片适用于平行、相近权重的信息；时间、因果、证据强弱及长短悬殊的内容不应为了凑三列而被压平。纸纹、手写字体、故意歪斜和低清晰度不是通用修复方法。

## 输出契约与插件整合建议

推荐核心流程为：用途与编辑需求 → 事实／素材清单 → 内容关系与页面大纲 → 原创版式 → 格式适配器 → 渲染检查 → 内容与视觉复审。先交付少量适配器，避免把所有引擎捆成安装负担。

| 输出模式 | 推荐路线 | 对用户明确说明 |
| --- | --- | --- |
| `editable-pptx` | PptxGenJS；研究材料可选 Quarto | 哪些文字、表格、图表和形状可以改；哪些元素仍为图片；交付源文件和数据 |
| `raster-pptx` | 图片工作流、Slidev PPTX、Marp 默认 PPTX | 每页是图片，正文无法原生选中或修改；保留逐页提示词／Markdown 与文字稿 |
| `html` | 按内容选择 reveal.js、Slidev 或 Marp | 浏览器交互、离线资源和静态导出的实际边界 |
| `print-pdf`／报告 | Quarto 或经验证的文档排版路线 | 检索、字体、分页、阅读顺序和可访问性需验证；PDF 不自动等于可访问文档 |

原生排版与生成插图可以组合：把已授权且明确为示意的插图放在指定区域，正文、公式和数据图由代码排版。这个组合应从源结构开始设计，不通过对整页生成图覆盖假文字来冒充可编辑重建。

每个适配器声明真实能力：`native_text`、`native_table`、`native_chart`、`speaker_notes`、`interactive`。能力可随版本变化，不以扩展名推断。第三方集成发布前记录确切版本／提交、源 URL、所复用文件、许可全文和修改说明；本调研的 `main`／`master` 链接是核查入口，不是版本锁定。MIT 声明与字体、主题、图标和内容许可分别记录。只参考的来源以链接和原创摘要进入参考库，不把整篇文章塞进技能上下文。

## 可机械检查与必须人工复审

| 项目 | 机械检查可做什么 | 限制与人工复审 |
| --- | --- | --- |
| 越界、遮挡、裁切 | 比较对象边界与页面；检查文本框溢出、缺失素材、渲染后的截断；区分声明的重叠与意外遮挡 | 坐标在框内不保证字形不溢出；合法叠图、透明图和光学对齐不能一律判错 |
| 层级与节奏 | 检查语义角色使用的字号、字重、行距及间距是否一致；发现异常小字、重复结构 | 不能用“标题必须多少点”替代观看距离、中文字体、页幅和信息密度判断 |
| 内容一致性 | 将标题、数字、单位、日期、标签、引用 ID 与事实清单对照；校验合计、图表数据及页码 | 一致不等于真实；来源可靠性、论证是否成立、删减是否失真、相关是否被误述为因果仍需人审 |
| 可编辑性 | 检查 PPTX 内原生文字、表格、图表和图片对象，识别只有整页图片的输出；抽查数据是否保留 | 出现文字对象不代表所有内容可编辑；复杂分组、断成碎片的文字及跨软件还原需实际打开检查 |
| 可读性与可访问性 | 检查缺字体、已知背景下的色彩对比、缺少替代文本、标题跳级、表头及阅读顺序元数据 | 色彩对比在照片底图上可能需人工判断；元数据存在不证明阅读顺序合理或替代文本有用 |
| 导出完整性 | 对照源大纲检查页数、顺序、点击展开状态、备注、缺图、链接及文字提取结果 | 需要在目标软件渲染全部页面并看缩略图总览与重点页原尺寸；一种渲染器通过不保证所有 Office 软件相同 |
| 风格与素材事实 | 提醒高频复用版式、无来源图像、未标明的示意图；记录素材出处及许可 | 不声称自动识别“AI 味”。人审受众适配、焦点、视觉比喻、可信度和是否仍显机械；许可范围也需按实际素材判断 |

建议检查结果用“通过／需修正／需人工判断／未验证”，附具体页码和证据。不要输出一个虚构的“人类感分数”，也不要将无溢出、低字数或高留白率当作沟通质量的替代指标。
